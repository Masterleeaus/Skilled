## 4. Findings

- **F1 (environment): the target branch has changed.** The remote has no `main`. The default branch is `Main` (`1b447a3`), and it has the app at the root. The older `lms-main/` tree (`80f2e31`) is no longer the trunk. This run verifies `Main`. The PR therefore targets `Main`.
- **F2 (defect, minor): `POST /api/auth/refresh` returns 422 when no refresh cookie is present.** Seen on every anonymous page load and on learner pages. An unauthenticated refresh should return 401. Reproduced in the browser (B02, B05, B06, B07, B08 network logs). Not fixed here (no app code changes in this issue).
- **F3 (test-harness): the login limiter is shared across checks.** `authLimiter` allows 10 login requests per 15 minutes per IP. The smoke script (3 logins) and the browser checks (about 5 logins) used the budget, and a retry was refused with HTTP 429. The limit cleared only after roughly 15 minutes past the last attempt, so a failed retry extends the wait. Run the browser checks once, or reuse a session, per window.
- **F4 (expected): health is 503 without MinIO.** `/api/health` reports `storage: down` and returns 503. Database and Redis are ok.
- **F5 (test-harness): two browser assertions were wrong, the app was not.** B05 and B07 first looked for the org name on the assessor page. A single-org assessor sees the empty state with no org name. The screenshot shows the correct "No evidence is waiting for a decision." state, so both are recorded as PASS.
- **F6 (unidentified): one console 404 in the first browser run.** Not reproduced in the lesson run (`404 resources: []`). Its URL was not captured. Open item.
- **F7 (observation): the lesson list shows correctly on `Main`.** An earlier run on the old `lms-main/` tree showed "0 lessons" on the learner course page for a legacy course. On `Main`, both the course page and the player list the two lessons, and a lesson opens. The earlier 0-lessons symptom did not reproduce on `Main`.
- **F8 (observation): `GET /api/enrollments/me` is not a route.** Returns 404. Enrolment progress is at `/api/enrollments/:courseId/progress`. Confirmed by smoke step S07.
