## 3. Findings

1. **No academy learner or assessor flow can be exercised on a fresh database from main.** The publisher holds every lesson behind the review gate (owner decision 23), and answer keys are held without an approval record in `assessment-publication-approvals.json` (not present in the repo). This is working as designed. It is recorded as BLOCKED, not as a pass, and no approvals were fabricated.
2. Route `PATCH /api/quizzes/:id/publish` is a PATCH, not a POST. This is correct; noted because the first draft of the script used POST.
3. `POST /api/auth/refresh` returns HTTP 422 when no refresh cookie is present (seen in the browser console on anonymous page loads). It is a validation error where a 401 would be expected. Not a flow failure; not fixed here.
4. **Application bug (learner UI, legacy course): the learner sees 0 lessons where the API returns 2.** Stopped here, not fixed.
   - API, student token: `GET /api/courses/nodejs-masterclass` returns HTTP 200 with module "Getting Started" containing "Welcome to the course" and "Setting up your environment".
   - API, student token: `GET /api/academy/curriculum/courses/cmw8a1hun00057dxrt6cyxjjt/outline` returns HTTP 200 with `"tracks": []`.
   - UI: `/courses/nodejs-masterclass` and `/student/courses/nodejs-masterclass` read the academy outline (`fetchCurriculumOutline`, `components/SharedCurriculumPlayer.tsx`), so they show "0 lessons" and "No lessons are listed on this track yet". The teacher course page reads the legacy modules and shows both lessons.
   - Effect: a learner on a seeded legacy course cannot open its lessons in the UI. Acknowledgement via the API (S08) still works.
